# lib

## Purpose

A utility library providing `StarfieldEngine`, a canvas-based particle animation system that renders an animated starfield with depth-based twinkling and smooth mouse-parallax effects. This is the primary visual engine behind the portfolio's "luxury observatory dashboard" aesthetic.

## Key files

- `src/lib/starfield-engine.ts` — The only file; implements the full particle engine with ~600 stars on desktop / ~200 on mobile, per-particle twinkling, three-layer depth, color distribution (gold 60%, blue 25%, white 15%), and a lerp-smoothed parallax driven by mouse position.

## Public interface

**Exported class: `StarfieldEngine`**

| Method | Signature | Description |
|--------|-----------|-------------|
| `constructor` | `(canvas: HTMLCanvasElement)` | Initialize with a canvas element |
| `start` | `() => void` | Begin the animation loop |
| `stop` | `() => void` | Cancel the animation frame |
| `updateMouse` | `(clientX: number, clientY: number) => void` | Update target mouse position for parallax |
| `resize` | `() => void` | Handle window resize and DPI rescaling |

**Consumed by:** `src/components/Starfield.tsx` exclusively.

## Dependencies

**External:** None — vanilla TypeScript using only the native Canvas 2D API.

**Internal consumers:**
- `src/components/Starfield.tsx` — instantiates and manages the engine lifecycle; feeds mouse position from `MouseContext`.

## Gotchas

- **Non-null assertion on canvas context**: Uses `!` assertions (lines ~71, ~127); will throw if 2D context is unavailable. `Starfield.tsx` adds a `console.warn` fallback but no visual recovery.
- **DPI clamped to 2×**: Device pixel ratio is intentionally capped at `2` to avoid performance degradation on ultra-high-DPI displays.
- **Mobile parallax disabled**: Parallax strength is `0` for viewports < 768px; particles render but do not follow the mouse. No intermediate breakpoint exists (jumps at 768px exactly).
- **Color string mutation**: HSL string is modified to HSLA via regex replace; assumes the exact format `hsl(h, s%, l%)` — deviations will silently produce incorrect alpha values.
- **Hard-coded lerp factor (`0.08`)**: Controls mouse-smoothing responsiveness; changing it affects the "feel" of the parallax follow.
- **Particles drift off-canvas intentionally**: No bounds checking for parallax offset — by design for "cosmic" feel, but may surprise contributors expecting containment.
- **No intermediate particle count**: Desktop uses 600, mobile uses 200; there is no tablet-range middle ground.
