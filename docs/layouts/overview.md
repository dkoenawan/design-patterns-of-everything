# layouts

## Purpose

Provides the base HTML document wrapper for the portfolio site. Handles the DOCTYPE, `<head>` metadata (SEO, viewport, color-scheme), global stylesheet import, and a `<slot />` for page-specific content. Currently the sole layout; all pages route through it.

## Key files

- `src/layouts/BaseLayout.astro` — The only layout file; accepts optional `title` and `description` props and renders standard HTML document structure with global CSS linked and a content slot.

## Public interface

**Component:** `BaseLayout` (Astro component)

| Prop | Type | Default |
|------|------|---------|
| `title` | `string?` | `"Solution Architect Portfolio"` |
| `description` | `string?` | Design patterns / architecture portfolio tagline |

Provides `<slot />` for child page content.

## Dependencies

**Internal:**
- `src/styles/global.css` — global font imports, CSS variables, and base element styling

**Consumers:**
- `src/pages/index.astro` — the only current consumer

**External:** Astro 5.17.1 (framework only; no npm packages needed by the layout itself).

## Gotchas

- **Single layout for all pages**: Any future pages that need a different structure must either modify `BaseLayout` or add a second layout file.
- **Hard-coded defaults**: Default title and description are baked in; multiple pages with unique defaults require prop passing or layout variants.
- **Dark mode hard-coded**: `<meta name="color-scheme" content="dark" />` is static; supporting light mode would require conditional rendering or a new prop.
- **Minimal responsibility by design**: Navigation, routing, and all interactive UI live in React components inside the slot — layout changes do not cascade to component logic.
