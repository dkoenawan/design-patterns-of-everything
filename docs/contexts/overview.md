# contexts

## Purpose

Provides React Context utilities for sharing real-time mouse position state across the application. Tracks the cursor's viewport coordinates globally via a passive `mousemove` listener, making them available to any component without prop drilling.

## Key files

- `src/contexts/MouseContext.tsx` — The sole file; exports `MouseProvider` wrapper component and `useMousePosition()` hook returning `{ clientX, clientY }`.

## Public interface

| Export | Description |
|--------|-------------|
| `MouseProvider` | Context provider component; wrap at application root (in `LandingShell`) |
| `useMousePosition()` | Hook returning `{ clientX: number, clientY: number }`; consumed by `Starfield.tsx` and `ConstellationPanel.tsx` |

## Dependencies

**External:**
- React 19.2.4 (`createContext`, `useContext`, `useEffect`, `useState`)

**Internal consumers:**
- `src/components/Starfield.tsx` — forwards position to `StarfieldEngine.updateMouse()`
- `src/components/ConstellationPanel.tsx` — calculates star proximity for glow effects
- `src/components/LandingShell.tsx` — wraps the app with `MouseProvider`

## Gotchas

- **Passive listener**: Registered with `{ passive: true }` — `e.preventDefault()` cannot be called inside the handler.
- **Viewport-relative only**: Provides `clientX`/`clientY` (not canvas-relative or scroll-adjusted). Consumers must combine with `getBoundingClientRect()` to get element-local coordinates.
- **No scroll compensation**: Works correctly for fixed-position elements (starfield) but scrollable panels need manual offset adjustment.
- **Single instance**: Nest `MouseProvider` only once at the root; multiple nested providers create redundant listeners and state.
- **Re-render on every mouse move**: Every `mousemove` triggers `setState`; all consumers re-render. React 19 batching mitigates this, but high-frequency animation consumers should use `useMemo`/`useCallback`.
